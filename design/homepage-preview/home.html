Your coding agent shouldn’t start every session as a stranger.

Reverie is memory for coding agents. It keeps the engineering conclusions your agent reaches while you work — root causes, constraints, decisions — reviewed by you and grounded in your repository, so later sessions can build on them.

Works with Claude Code, Cursor, OpenCode and Codex. Memory stays on your machine.

How it works Read the research

The bottleneck isn’t intelligence. It’s continuity.

You spend an afternoon with your agent working out why users are being logged out at random. Together you find the cause — the cache is cleared before the token refresh finishes — fix it, and rule out an alternative. Then the session ends, and the next one begins without any of it.

A bigger context window holds more of one session; it doesn’t carry understanding into the next. A saved transcript keeps everything that was said, dead ends included.

The hard part isn’t storing more. It’s deciding what deserves to be remembered.

How it works

Three steps, across the session boundary — and you decide what crosses it.

  1. 1Extract

    When your agent works something out, it hands its reasoning to Reverie. Reverie keeps the conclusion and rejects the rest: facts anyone could read in the code, descriptions, the play-by-play.

  2. 2Review

    Conclusions wait in session memory, already usable in that session. When you end the session, you accept, reject or skip each one in your terminal. Only what you accept becomes long-term memory.

  3. 3Retrieve

    In a later session, your agent asks for what’s relevant — after it has read the code, not before. It gets back conclusions with their confidence, scope and files, marked as past understanding to verify.

Memory that can change its mind.

One conclusion, followed through later sessions.

Evidence moves confidence. A supporting conclusion raises it, a contradicting one lowers it, and conclusions nobody uses fade.

Contradictions stay visible. The challenged conclusion isn’t overwritten; if the conflict persists, it comes to you as an open question.

Replacements keep history. Accepted conclusions are never rewritten: a new one supersedes the old, which is kept and linked.

The code has the last word. If the files a conclusion cites are deleted, conclusions about that code are retired; general principles are kept.

What you’re installing

A local memory
One SQLite file in your home directory, shared across your projects. No account, no cloud service, no vector database.
An MCP server
Your agent starts it and calls four tools: ec_observe, ec_query, ec_get_summary, ec_reconsolidate.
Agent setup
The installer configures Claude Code, Cursor, OpenCode and Codex. Other MCP clients can be set up by hand.
Your choice of model
Extraction uses the LLM endpoint you configure — hosted, or local through Ollama. Embeddings and retrieval always run locally.

Built by measuring what didn’t work.

Reverie’s first version loaded relevant memory into the agent’s context before it started work. On our benchmark, that made the agent worse: it trusted what it was told instead of reading the code. That result shaped everything after it — keep only conclusions, review them, and let the agent ask when it needs to.
